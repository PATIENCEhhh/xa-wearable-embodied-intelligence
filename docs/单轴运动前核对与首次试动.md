### 1. 旧零偏与当前姿态未经现场对照

`control_layer_cfg.h` 中槽位 5 的减速比为 1，方向为 +1，零偏为 6.010 rad。实际换算为：

```text
motor_target = joint_target * direction * gear_ratio + zero_offset
joint_state = (motor_state - zero_offset) / (direction * gear_ratio)
```

将本次位置代入旧标定得到约 -52.32°。这只是旧配置下的计算结果，不是已确认的实际肘角。不能在这个状态直接下发关节 0 rad：旧换算会令电机目标变为 6.010 rad，距离当前约 0.913 rad（约 52.3°），与首次小幅试动目标不符。

### 2. 原动作工作区与当前原始位置不一致

原弯举配置 `CONTROL_REHAB_CURL_HARD_MIN_RAW_RAD/MAX` 为 6.238..7.829 rad，另一处助力槽位 5 的硬边界为 6.000..8.264 rad。当前约 5.0968 rad 低于两处旧下界。

这些是不同动作的历史配置，不足以单独判断机械当前是否超限。应先核对姿态、坐标定义和现场机械止挡，不能简单扩大限位或改零偏来放行，也不调用旧弯举/固定动作使其自行回到旧工作区。

### 3. 关节命名与槽位映射有不一致

- 康复模块：`rehab_joint_map.c` 的 elbow 使用 `CONTROL_REHAB_DEFAULT_M33_JOINT=5`，弯举配置也指定 5。
- ROS 配置注释：slot 4 对应 elbow_lift_joint，slot 5 对应 shoulder_abduction_joint。
- 已有无线页面将 4 显示为肩部抬臂、5 显示为肘部屈伸。

必须由实物标签/原接线确认哪一个电机实际驱动肘部，不能仅依赖 UI 名称。当前仅按数字槽位发送只读请求，不更改 ROS 或康复模块映射。

### 4. 现有 Wi-Fi 服务只有查询，没有运动和停止

`wifi_debug.c` 与 `m33_dap_diag.c` 只允许 ID、位置、速度、模式四类查询；当前浏览器不能使能、移动或停止电机。本轮不更改这项接口约束。若首次试动要求全程通过 Wi-Fi，应先实现并验收受限试动与停止入口，以及 M33 本地超时、反馈及位移边界保护，再经电机断电确认安装固件。

原工程有 `control_motor_stop(joint,false)`，以及串口 `cmd_motor_stop <joint> 0`。它发送私有协议 STOP 帧、不清故障；发送返回成功不等于电机物理停止。该入口尚未在现场执行和验收。

### 5. 不直接使用通用位置命令作为首次试动

`control_motor_csp_prepare()` 当前先切换模式、使能，然后才写限流、速度上限；之后另一函数才下发新位置。尚不能排除使能瞬间已有目标或旧参数生效。通用 `cmd_motor_pos` 还使用默认限流参数 0，且没有为单次试动提供本地总时限。ROS 审核限位也不能视为该直接 API 已执行同样保护。

首次试动入口应在使能前确认并设置受限目标及约束，需按所用电机协议核对生效顺序；发生任一步错误都执行停止，停止失败应明确报错。不能仅靠电脑脚本结束或 Wi-Fi 断开来保证停止。

## 后续执行次序与验收

1. 现场确认未穿戴、支撑稳固、肘部不在机械止挡处、人员可立即切断电机动力；确认 5 号电机的实物关节，以及当前大致姿态。
2. 在现场信息基础上确认零位、方向、比例及机械可用行程。本轮不改电机持久零点，不保存未经验证的新标定。
3. 确定实际执行链路，准备可独立触发的 STOP 和 M33 本地停止保护。先检查其命令处理和错误返回，再在支撑条件满足时现场验收停止/失能行为。
4. 首次动作只选已确认的单轴，从重新读取的当前位置开始，在已验证的安全方向内试动。候选位移为约 1°，候选速度上限约 0.02 rad/s；二者仍需结合机械余量确认，限流须按实际型号及负载确定，不能把候选值当成已批准执行参数。
5. 执行时只允许一次有总时限的试动，不自动往返。反馈过期、位移越界、速度异常、查询失败或总时限到达时由板端停止。记录目标、起点、终点、返回码，以及现场观察到的关节和方向。
6. 停止后继续读取位置和速度，结合现场观察判断结果；单次速度近零不能作为完整停止验收。完成单轴核对后再讨论其他轴或组合演示。
