# 三轴保持与肘部弯举 v5

日期：2026-10-16。用途：iCAN未穿戴机构演示，恢复原工程控制路径，不引入ROS或SDK。

用户观察到5号弯肘时整段前臂向侧面偏转，并要求弯肘期间固定另外两个电机。本次实现4、6号保持启动时的位置，5号先屈曲再伸展。侧偏现象尚不足以证明具体关节或固定件的根因；本次修改按用户要求增加主动位置保持，不把它写成机械问题已经排除。

**最新状态：v5三次上电整轮屈伸均获板端DONE成功。最近一次按用户请求重跑，state13、run_result0，4/6无保持故障，首次错误0；用户随后反馈“现在真没毛了”，暂按“没有问题”的口语反馈记录，未据此补写具体侧偏、抖动或落下观察。追加STOP后确认不再活动、无授权；现场静止与关闭动力仍未确认。**

## 三个电机的职责

| 电机 | 本轮行为 | 位置目标来源 | 电流上限 |
|---|---|---|---|
| 4 | 主动位置保持 | 本轮使能前采集的原始位置 | 1.0 A |
| 5 | 先屈曲、停留、再伸展、停留 | 新标定旧弯举：6.439812851 → 5.021363544 rad | 2.0 A，沿用当前旧弯举配置 |
| 6 | 主动位置保持 | 本轮使能前采集的原始位置 | 1.0 A |

4、6号不接收用户输入角度，也不回到历史零点。停用期间先将本轮采集的原始位置写入loc_ref并读回；使能时复用旧接口`control_motor_position_control_with_current_limit`。传入旧接口前，按原配置的方向、减速比和零偏把采集位置逆变换为关节坐标，旧接口再正变换回同一原始目标；速度也按减速比换算，保证电机原始指令上限为0.12rad/s。保持限流采用原固定动作的1A量级，不能保证足够承载；保持不住就退出，不自动提高电流。主动保持不是机械锁定，仍须可靠支撑。

5号保留0.12rad/s指令速度、0.35rad/s反馈速度保护、0.030rad到位容差、连续5个到位样本及端点500ms驻留。目标相对伸直参考约84.14°与2.86°；发生机构侧偏时，电机编码器角不能直接等同于纯肘屈曲角。其原有单段20秒、使能42秒及流程45秒时限保留。

## 启动和停止顺序

1. 上电默认空闲，无自动使能。经本机DAP一次性RAM授权后，才接受一次三轴动作请求。
2. 串行采集4、6号各5组位置/速度。原始位置须有限且处于协议可表示范围，采样漂移不超过0.002rad。当前已安装的准备检查修正v2使用五次有符号速度均值的绝对值不超过0.03rad/s、单次绝对速度严格小于0.10rad/s，并独立限制逐段位移及累计绝对路程；各自预算为0.0004rad量化裕量加0.03rad/s乘相应经过时间。不能用正负均值抵消真实往复运动。此前v1使用单次0.03rad/s检查，在首次测试中触发退出。协议范围不是已测机械硬限位。
3. 分别STOP并确认停用状态，再写入、读回CSP模式5、1A限流、旧配置0.12rad/s速度上限及采集到的位置保持目标。两轴都准备完成后，才开始使能；使能前再读位置，拒绝已被移动的基线。
4. 依次通过旧CSP完整位置控制入口使能4、6号，核对新鲜运行反馈。旧入口内部按模式、使能、限流、限速、目标的顺序发送；因此上一步必须在停用态完成两轴的同一目标和限流预置，不能删除。两轴都确认进入保持后，才启动5号原弯举准备和运动流程。
5. 4、6号在准备另一轴及整个弯肘过程中持续监控。原始位置相对基线偏移超过0.035rad（约2°电机角）、速度超过旧配置0.35rad/s、状态/故障异常或反馈超过250ms未更新，均导致整组退出。此阈值是相对漂移保护，不是机械限位。准备阶段的静止采样判据仍按第2步执行。
6. 成功、失败、取消及外部STOP都汇总到整组停止路径：先向5号，再向4、6号发送STOP。每轴各自最多3次，间隔至少50ms；某一轴发送失败也会继续停止其他轴。5号旧包装器自身退出时可能已经发过STOP，整组停止会再次确保三个轴都收到请求。

**本版本完成后不持续保持三轴。STOP会停用电机、解除主动承载，机械支撑必须一直保留。STOP发送成功不代表物理静止或姿态保持已经验收。** 保持准备阶段最多10秒，整组看守最多55秒；主机等待最多58秒，不自动重试。上述均是软件保护，网络或CAN故障时现场仍需能够直接关闭电机动力。

## 实现与诊断

- `bench_support_hold.c/.h`负责4/6采样、参数读回、使能与保持监控，独立于RT-Thread，便于实际状态机故障注入。
- `m33_bench5.c`统一调度保持与原5号弯举状态机，独占4/5/6的控制发送。其他线程的运动写入、归零及旧ROS控制仍被拒绝；外部STOP仍可锁存取消。
- 参数查询同时只有一个在途请求，回复必须匹配电机ID、索引、0x11读回复类型、新序号及时间。运行时的保持监控只读各电机反馈缓存，不抢占5号参数查询。
- 已核查当前私有协议反馈解码：反馈缓存的pos/vel直接保存电机原始值。保持比较不再做关节换算，避免把接口头文件的泛化描述当作当前路径的实际单位。

服务`arm-wifi-debug-v5`，本版邮箱ABI 8、长度64字节，动作配置`legacy-curl-j5-hold-j46-v4`；描述符版本标识与本机授权工具同步更新。镜像已在断动力条件下写入，DAP读回描述符符合ABI8；HTTP运行版本核对尚未完成。当前工具拒绝旧v1/v2/v3，旧单轴工具也不能授权三轴固件。

| HTTP接口 | 行为 |
|---|---|
| GET `/api/status` | 新版本、双核运行、授权状态及保持/停止轴列表 |
| GET `/api/motor/{4,5,6}/{id,position,velocity,mode}` | 空闲时原始单位查询 |
| GET `/api/bench/5/status` | 整组是否活动、最终结果和汇总STOP发送结果 |
| GET `/api/bench/5/detail` | 5号起点、最后监测位置、目标及整组阶段的5号STOP尝试数 |
| GET `/api/bench/5/support` | 4/6基线、保持状态机阶段、失败轴与首次失败阶段 |
| GET `/api/bench/5/failure` | 5号首次错误、失败状态、参数索引及使能/目标尝试次数 |
| GET `/api/bench/5/trip` | 首次保持监控触发原因、原始位置/速度/基线及使能尝试掩码；无有效样本时为null |
| POST `/api/bench/5/curl` | 一次授权后启动三轴协同的一轮弯举 |
| POST `/api/bench/5/stop` | 停用4/5/6三轴并锁存取消；名称中的5是管理入口 |

`support`中阶段0=空闲、1～11=采样/准备/使能、12=保持准备完成、13=故障；只有阶段12且两轴反馈合格时才启动肘部。基线在采样完成前可能为默认0，不能把它当作已测位置。5号首次失败记录与支持轴失败记录分开保留；追加取消可能使最终运行码变为-26，不抹去首次错误。

```powershell

.restore-tools/Scripts/python.exe tools/wifi_arm_debug.py support

.restore-tools/Scripts/python.exe tools/wifi_arm_debug.py stop 5
```
