# 机械臂 Wi-Fi 只读调试

> 2026-10-16更新：目前安装v3，包含原只读查询、5号STOP以及经本机DAP临时授权的0.5°单次试动。默认无授权，不自动运动。本文下方为v1查询实现与历史验收；当前接口、授权方式及验收以[5号电机单次试动-v3](5号电机单次试动-v3.md)为准，不能再把整个服务描述为只允许GET或完全只读。

电脑与开发板接入同一局域网，通过 M55 的 HTTP 服务读取板卡状态、提交原 M33 电机参数查询。无需 ROS、NanoPi、无线 DAP 或电脑端串口。首次安装固件仍使用板载 KitProg3；本服务不提供无线烧录或断点调试。

## 接口与操作

本轮已实测的浏览器地址：<http://192.168.5.182:8088/>。电脑和板卡均连接 `GDUT-AD`。IP 由 DHCP 分配，不能假定永久不变。页面点击查询，不会自动持续查询电机。

| 请求 | 用途 |
|---|---|
| `GET /api/status` | M55 tick、Wi-Fi 就绪、M33 配套校验、轮询计数、请求及完成序号 |
| `GET /api/motor/4/id` | 查询肩部抬臂电机设备 ID |
| `GET /api/motor/5/position` | 查询肘部电机位置参数 0x7019 |
| `GET /api/motor/6/velocity` | 查询上臂旋转电机速度参数 0x701B |
| `GET /api/motor/5/mode` | 查询模式参数 0x7005 |

三个电机槽位均支持 `id`、`position`、`velocity`、`mode`。只允许 GET 和这些完整路径，不接受任意参数地址、任意 CAN 帧、shell、使能、运动、复位或 Flash 操作。当前诊断服务在局域网提供只读接口，无身份认证，不能开放到公网。

电脑命令示例，在工程目录运行：

```powershell
python tools/wifi_arm_debug.py status --host 192.168.5.182
python tools/wifi_arm_debug.py position 5 --host 192.168.5.182
python tools/wifi_arm_debug.py velocity 6 --host 192.168.5.182 --count 10 --interval 1
```

脚本使用 Python 标准库、绕过系统 HTTP 代理；不要求电脑安装串口或 DAP 库。页面和脚本可将位置、速度的 `value_bits` 解码为原始 float。数值仍为电机协议参数，未应用关节零偏、减速比或方向标定，不能直接当作关节角或控制目标。只有 `ok=true` 且 `result=0` 才是本次匹配的电机回复。

## 双核交互与错误处理

M55 通过 SRAM 访问现有 M33 诊断邮箱；原 M33 主循环继续调用既有电机查询函数，网络线程不能直接控制 CAN。M33 此次改动只让邮箱独占两个 32 字节缓存行，原白名单、控制流程和电机协议不变。M55 在读前失效数据缓存，先写请求参数并刷缓存，最后发布请求序号；等待完成后只读结果。

邮箱地址及 SRAM 描述符绑定到配套 M33 ELF；启动魔数、ABI 版本、邮箱地址和长度、四字标识不匹配时拒绝提交查询。描述符不访问 M33 独占代码区。运行 `python tools/check_wifi_debug_binding.py` 可核对源码绑定；更新 M33 后必须重新检查，必要时更新并重建 M55。这是当前板端诊断适配，不是跨版本稳定的 SDK 通信协议，也不提供完整镜像真实性校验。

只同时处理一个客户端。单次收发超时为 2 秒，未完整的请求头还检查累计接收时间；最迟检查前的一次接收仍可能占用一个收发超时，约 2～4 秒后释放慢客户端，完成后关闭连接。电机查询间隔限制至少 350 ms，M33 等回复约 1 秒，M55 等主循环最多约 1.8 秒。无线查询期间不要同时使用 `query_m33_dap.py` 或其他同类参数请求，原电机协议不携带请求序号，无法彻底排除其他请求的同 ID、同参数回复。

| 结果 | 含义 |
|---|---|
| HTTP 200，`ok=true` | 本次诊断查询成功，或板卡状态接口正常 |
| HTTP 200，`ok=false`、`result` 非零 | M33 已处理请求，但 CAN 发送失败或电机回复超时；不能把零值当作实测值 |
| HTTP 404 / 405 | 路径不在白名单 / 方法不允许，不提交电机请求 |
| HTTP 429 | 查询过快，未提交新请求 |
| HTTP 503 | 配套固件不匹配、邮箱忙、请求被其他来源修改或主控重启 |
| HTTP 504 | M33 未在限定时间内完成；请求可能仍在处理，不覆盖邮箱 |

`m33_binding=true` 表示地址魔数与 ABI 描述符匹配，不单独证明主循环活跃；需比较两次 `m33_polls` 是否递增。HTTP 状态接口不发送电机查询。

## 临时入网与供电

M33 和 M55 使用同一调试串口，当前串口命令可能由 M33 接收。因此提供首次安装时的本机配置工具，使用 KitProg3 将 SSID、密码写入 M55 RAM 的专用入口，再由 M55 线程调用无线驱动入网。该入口不在 HTTP 上开放，不复位、不暂停 CPU、不操作电机，也不写配置 Flash。

```powershell
.restore-tools/Scripts/python.exe tools/wifi_debug_setup.py --ssid GDUT-AD
```

工具通过隐藏输入提示读取密码，凭据不出现在命令行、临时文件或日志中。处理后板端清零临时密码缓冲区，本轮实测输出 `join_result=0; temporary_password_cleared=True`。驱动在 RAM 中保留连接所需信息。该工具依赖 pyelftools、OpenOCD 和与板上固件一致的 M55 ELF；日常 `wifi_arm_debug.py` 无这些依赖。

入网完成后，有线调试进程已退出，电脑直接通过 Wi-Fi HTTP 诊断；开发板仍需保持供电。当前未保存凭据，整板断电重启后应重新临时配置，自动重连不能当作已验收。HTTP 不提供无线烧录、断点、单步或运动控制。

本轮为构建修复两处原兼容问题：触摸驱动将寄存器号组装为实际命令缓冲区后传给读取函数，显示驱动补充延时函数声明所需头文件。完整构建通过，触摸显示和离线语音仍不在本次功能验收范围。
