## 本次实现及默认门禁

M33新增`bench5_guard.c/.h`纯C状态机和`m33_bench5.c/.h`适配线程。线程每10ms调度，与HTTP处理和100ms主循环分开。只操作5号，使用电机原始位置，不套用旧零偏6.010 rad，也不调用旧整套弯举动作。

默认配置固定为`locked=1, direction=0, current_a=0`。HTTP试动入口和M33准入均关闭；网络不能设置方向、电流、原始目标或任意寄存器。禁止仅为了放行而修改门禁。解锁前还需确认实物屈曲方向、传动比例、可用行程、适用限流、单一控制源及访问控制，并核对所用电机在失能时写入CSP参数的协议行为。

未来试动的候选软件边界：相对本次起点0.5°电机角度、限速0.01 rad/s、使能后最多1.5s、从请求开始总计最多4s。电流必须有限且大于0、不高于0.5A；这只是软件上限，不代表任意灵足型号和负载都适用。每次启动最多一次试动，不自动往返。

准备顺序：读取新位置与速度、发送STOP、写CSP模式并读回、写限流并读回、写限速并读回、把当前位置写为保持目标并读回、再次读取位置检查漂移，再使能并写入相对目标。每个参数请求最多等待250ms，超时后的缓存回复也拒绝。运动时交替查询原始位置和速度，反向越界、超程、超速、非有限数、反馈超时、IO失败或本地总时限到达均进入停止流程。

STOP最多重试3次；发送失败可见。这个线程是本地软件保护，不是硬件安全回路。CPU停机、任务无法调度或CAN链路断开时，不能保证软件STOP生效，现场仍须能立即切断动力。发送成功也不是物理停止验收。

## Wi-Fi接口v2

浏览器：<http://192.168.5.182:8088/>，同一局域网GDUT-AD。重启后临时RAM入网配置可能需要重新下发，DHCP地址也可能改变。

| 接口 | 行为 |
|---|---|
| `GET /api/status` | 双核状态，`queries_read_only=true, trial_locked=true`；因增加STOP，`read_only=false` |
| 原有`GET /api/motor/{4,5,6}/{id,position,velocity,mode}` | 保留只读查询 |
| `GET /api/bench/5/status` | 测试快照：state、flags、active、run_result、stop_send_result |
| `POST /api/bench/5/stop` | 接收停止请求；随后查状态，不能把该请求的ok当成物理停止 |
| `POST /api/bench/5/trial` | 固定返回HTTP423 `physical_validation_required`，不提交M33请求 |

快照state=0表示空闲，12停止中，13软件流程结束，14软件故障/取消；flags位0=锁定、位1=本次启动已使用、位2=活动或待处理。`run_result=-26`表示取消/请求停止。`stop_send_result`只有在停止流程执行后才有解释意义，初始0不表示已经发送过STOP。`physical_stop_verified`始终为false。

HTTP同一时刻服务一个客户端，查询或慢客户端会延迟网络停止的处理，因此页面按钮不是急停回路。STOP没有身份认证，仅适用于当前受控局域网；运动入口仍锁定，不能直接照搬此访问策略开放运动。

电脑使用：

```powershell
python tools/wifi_arm_debug.py status
python tools/wifi_arm_debug.py bench
python tools/wifi_arm_debug.py stop 5
```

诊断邮箱ABI版本升为2，长度仍64字节，描述符与邮箱地址仍为0x240BD600和0x240BD620。op5/6/7分别为停止、锁定的试动请求、快照，仅支持5号。op>=5的index是状态，value_bits是flags，uid_lo/uid_hi是运行/停止发送结果，不能按设备UID或位置解释。使用期间不并行发起其他DAP邮箱或参数查询。
