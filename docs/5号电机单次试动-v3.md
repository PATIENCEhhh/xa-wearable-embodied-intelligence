## 当前用途

本固件专用于未穿戴、前臂有机械支撑的5号灵足RS00单轴试动。已采样确认屈曲对应原始角度增加；不再要求重复精确摆正伸直。试动每次重新读取实际位置，只请求相对该位置增加约5°原始电机角度，不使用旧SDK零偏6.010 rad，不设置永久零点，不自动回程。

4、5、6号只读查询及STOP保留。统一CAN出口禁止原ROS、本地康复模式、串口命令等其他线程发送电机使能、运动目标、写参数或置零；只有bench5线程可向5号准备固定参数和试动。标准电机控制帧也不能绕过该出口。两个直接CAN旁路经检查仅发送固定0x322状态帧。此版本属于单轴台架固件，不能据此声称旧康复模式仍可运行。

## 固定流程与边界

| 项目 | 本次实现 |
|---|---|
| 相对行程 | +0.0872664626 rad，约5°原始电机角度 |
| 速度参数 | 0.01 rad/s，约0.573°/s |
| 电流参数 | 0.2 A；不会自动增加，不保证能承载机构 |
| 本地使能时限 | 12秒，含使能反馈等待；理论行程约8.73秒 |
| 总流程时限 | 15秒 |
| 无进展退出 | 1秒未沿目标方向累计前进0.001 rad且未到目标，报-27 |
| 单次参数回复等待 | 250毫秒；迟到回复不能覆盖超时 |
| STOP | 最多3次发送，每次间隔至少50毫秒；不清故障 |
| 重复启动 | 每次板卡启动只接收一次；STOP锁存，失败不自动重试 |

流程：五对新位置/速度确认稳定 → STOP → 确认新鲜状态反馈为停用且无故障 → 写入并读回CSP模式5、电流、速度及当前位置保持目标 → 再查位置未漂移 → 使能 → 确认新鲜运行状态反馈且无故障 → 写入相对目标 → 交替监测位置/速度 → STOP。

参数报告增加回复类型与接收序号，0x12写回显不能冒充0x11读回；接收序号也用于接受同一个tick内的新回复。运行状态反馈与参数run_mode是两类数据：读到模式5不等于电机已使能。

速度判断结合五次有符号速度均值（阈值0.03 rad/s）、单次硬上限0.1 rad/s、连续位置变化与总位移边界。位置差分限值为0.03 rad/s乘采样间隔，另加0.0004 rad量化裕量；另以至少200ms窗口检查累计绝对位置变化，预算为0.0004 rad加0.03 rad/s乘窗口时长，避免每次量化裕量累积或往复位移抵消。反向或超程裕量0.002 rad。使能前五次位置相对初值的漂移也不得超过0.002 rad。离散采样不能保证检测采样间完全抵消的运动；实物读数波动原因尚未确认。

这些是软件保护。网络STOP不是独立急停，CAN断线时也无法保证电机收到STOP。STOP可能解除承载力矩，现场必须保留机械支撑和断动力手段。

## 临时授权与操作

默认启动无授权、不运动。主机工具生成随机128位令牌，通过有线KitProg3临时写M55 RAM，同时给M33一次性授权。M33授权最多等待约60秒；重启清空。令牌不写文件/Flash，不放URL、不在网页展示；M55在提交第一次有效请求之前擦除令牌，重发、网络超时和失败均不会自动再次启动。外部STOP在CAN出口锁存取消，后续使能和参数写入会被拒绝。

本次采用局域网明文HTTP，令牌不提供链路加密。首次授权仍保留有线DAP，动作请求、运行结果和查询走Wi-Fi；这不是无线烧录或断点调试。

```powershell
# 只查询，浏览器也可访问 http://192.168.5.182:8088/
.restore-tools/Scripts/python.exe tools/wifi_arm_debug.py status
.restore-tools/Scripts/python.exe tools/wifi_arm_debug.py bench
.restore-tools/Scripts/python.exe tools/wifi_arm_debug.py detail

# 必须先经现场确认已上电、未穿戴、前臂有支撑且行程无阻挡。
# 此命令会通过DAP临时授权，再经Wi-Fi启动一次约5°试动，不会自动重试。
.restore-tools/Scripts/python.exe tools/bench5_trial.py --supported-and-clear

# 请求STOP，随后查bench/detail，不能把请求接收ok当成物理停止。
.restore-tools/Scripts/python.exe tools/wifi_arm_debug.py stop 5
```

| POST `/api/bench/5/stop` | 锁存停止；不需要动作令牌 |

邮箱ABI版本3，64字节；描述符0x240BD600、邮箱0x240BD620。op5/6/7为STOP/单次试动/快照；op8为详细数据，value_bits、uid_lo、uid_hi分别是origin/position/target的float位模式，reply_tick为STOP尝试次数。重新链接后必须执行`tools/check_wifi_debug_binding.py`；不能并行用DAP邮箱和Wi-Fi查询。
