# iCAN：以旧工程恢复功能

用户当前优先级：恢复已经实现并实测成功的旧功能，暂停SDK和通用动作封装；交互使用本地LVGL，不使用小智。当前恢复主工程是 `xa-wearable-embodied-intelligence`，不是旁边的 `xa-ican-original-voice` 通用动作候选副本。

## 本轮采用的既有流程

直接使用原工程的 `m33_bench5.c`、`bench_support_hold.c`、`bench5_guard.c` 和原 `rehab_curl_planner`。4、6号通过旧完整CSP入口保持启动前姿态；5号先屈曲、再伸展，沿用5.021363544和6.439812851原始rad端点、0.12rad/s命令速度、2A限流；保持轴各1A。独占原CAN出口，其他线程不能抢写运动目标。

触屏使用已有 `ican_curl_panel.c` 及64字节跨核邮箱，不经过新副本的通用固定动作执行器。明确点击启动后连续往返；正常停止且三轴STOP发送成功后允许再次启动。按停止会释放主动保持力，机构需要支撑。4、6号保持的是启动时姿态，不自动归回历史标定点，应先摆好希望保持的姿态。旧流程在心跳丢失、反馈异常、保持漂移及控制故障时退出，故障检查后复位。

本轮不改变旧电机执行源码。仅在M55关闭语音服务自启动，以满足已确定的本地LVGL交互选择。小智自动连接开关本就为0。之前的新副本保持修正候选未烧录，不作为本轮恢复基础。

1. 优先恢复并验收：约90°屈肘往返，4、6号保持，LVGL启动、连续循环和停止。
2. 旧本地菜单已有30°、60°和端点停留动作配置，离线回归已通过，逐项实物验收后使用。
3. 旧菜单抬臂仍为未就绪；不能把菜单入口当作已接通电机。之后根据已采集端点，在旧执行链路上恢复抬臂、旋转。
4. 康复、助力和录制回放继续作为后续旧功能恢复项目；当前不宣称这些链路已完成现场验证。
